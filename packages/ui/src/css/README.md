JSswift UI CSS source files.

Edit CSS here, not in `packages/ui/dist/css`.

Build outputs are generated with:

```bash
npm run build:ui:css
```

Generated outputs:

- `packages/ui/dist/css/*` for npm packages
- `pages/_jsswift-fe/css/ui.css`
- `pages/_jsswift-fe/css/min-ui.css`
- `pages/_jsswift-fe/css/ui.min.css`


`ui.css` remains the full compatible bundle. `ui-light.css` and `ui-light.min.css` omit breakpoint utilities but retain base tokens, component/mobile styles and unprefixed utilities generated by `cms-dev/make-responsive-css.mjs --base-only`. Add `responsive.css` after the light bundle for breakpoint props. All props remain available in JavaScript.

## Extracted component styles

`components/<component>/` owns component-specific sections; `shared/` owns native rules, utilities, common surface/effect rules and compositions spanning several components. `ui-components.css` is the ordered source entry. Every rule is in an extracted file, imported at its original cascade position.

The source-only local imports are expanded by `tools/ui-css-source.mjs` during the CSS build. Use quoted relative paths without media/layer conditions. Missing files, unsupported imports and cycles fail the build. Generated `ui-components.css`, `ui.css` and `ui-light.css` contain the expanded styles; do not serve the source entry directly.

Base/effect sections and numbered `styles-NNN.css` continuations preserve the existing cascade. The entry file determines order; never concatenate component directories alphabetically or move all late overrides next to the base. Shared compositions remain shared, rather than duplicated among components.

All component families, including Upload/BoxUpload, advanced fields, display/content, navigation, feedback, shells, Table and overlays, are migrated. Datepicker/Calendar share Date styles; card section helpers share Card styles; RouteTab combines its own styles with Tabs; ContextMenu uses Menu styles. Row/Col use the canonical generated responsive utilities, Form uses native/shared styles, and the Loading service owns its existing inline styling. These entries intentionally have no dedicated CSS file.

`modules.json.components` and `styles.shared` register all extracted files. `cssOwnership` retains the conservative selective CSS contract: common/native/unknown and complex selectors remain included as before. The CSS watcher includes nested source directories. Responsive source remains `cms-dev/make-responsive-css.mjs`.
